# 倍福型号资料库实施方案

用户已确认：私有仓库维护结构化资料，生成 Markdown 快查和浏览器搜索网页。先仔细核查官网产品选型页中的简介、规格及配置关系，再实现查询。

## 数据范围

首批覆盖存储卡、CFast、SSD、操作系统、部分 IPC/CX 主机、I/O 及相关选件附件。逐条保存官方来源、页面区段、查阅日期、适用条件。首批不是全产品目录；待扩充范围公开列出。

## 架构与边界

- `data/catalog.json`：唯一维护数据，包括型号、来源、配套关系、资料差异、待查清单。
- `src/search.js`：不依赖界面的查询函数，支持型号归一化、中文别名、多词 AND、分类/主机/资料状态筛选；完整型号优先。
- `site/`：查询界面源文件；本地浏览器搜索，不调用外部服务。
- `scripts/build.mjs`：校验引用、生成 `dist/` 和 Markdown。未知字段不自动补全；配套关系只来自明确来源。
- `tests/`：搜索与数据完整性检查。
- `docs/维护指南.md`：资料录入、冲突处理、验证及私有部署边界。

数据流：官网查阅 → 人工结构化录入 → 校验 → 网页与 MD 生成 → 私有仓库审查。保留每个来源观察，不让生成程序裁决矛盾。

## 实施顺序

1. 研究官网选型页，整理首批资料及差异记录。
2. 编写搜索验收测试，验证功能缺失，再实现搜索。
3. 完成数据校验、Markdown 生成及搜索网页；支持空结果、详情、条件显示、来源跳转。
4. 运行数据与搜索测试，检查桌面和窄屏界面，编写维护与部署说明。

## 约束

- 当前目录未关联 GitHub 仓库；不假定用户账户或远程地址，不公开发布。
- 静态网页不是登录系统。后续私有部署必须由托管层保护页面、数据和附件全部路径。
- 本工具不连接 PLC，不执行控制，不做自动选型批准。来源核对不是实机兼容测试。
- 不编造修订日期、PDF 页码、产品停产状态或库存；公告型号保留公告状态。
- 官网地区版本单独记录；不能把查阅时间当作发布时间。

## 验收重点

完整型号可直达；部分型号和多词搜索有效；类别与主机筛选可组合；同型号不重复；无结果可恢复；每条参数能追溯来源；产品状态与资料核查状态分离；手册未列出不推断不支持。
